# 本地敏感资料加密与安全复测结果

日期：2026-10-31（Asia/Kuala_Lumpur）。范围：本地 main 工作区，基准 `74f6119` 加本轮未提交修改。没有推送、部署或连接真实硬件。

## 总体结果

本轮加密与安全测试通过，现有 Web 功能回归通过。旧资料已在原本的隔离本地数据库中迁移，不是删除后重建账号。姓名、邮箱、观察自由文本及审核意见在数据库中保存为认证密文，授权接口仍返回正常文本。

最初迁移：5 个用户、251 条观察、99 条审核，共 611 个原明文字段。账号 ID、密码哈希、角色和关系保持不变。回归测试产生的新记录也通过密文审计；最终审计时共 973 个敏感字段全部通过，明文字段数为 0。计数会随虚构测试记录增加而变化，不代表真实调查数据。

## 安全评估、整改与复测

| 发现／风险 | 整改 | 验证证据 |
| --- | --- | --- |
| 数据库中的姓名、邮箱和观察／审核自由文本原为明文 | AES-256-GCM，随机 IV、认证标签、字段／所属行身份绑定 | 数据库密文审计、Unicode／空文本往返、跨行／跨字段和标签篡改拒绝通过 |
| 直接按邮箱查询与唯一约束依赖明文 | 使用独立派生密钥的 HMAC 索引，唯一约束保留 | 登录、重复邮箱、注册、用户管理及 fixture 更新通过；索引与解密邮箱一致 |
| 错误密钥或损坏数据可能引出不安全回退 | 缺失／错误密钥和非密文严格拒绝，不提供明文兼容读取 | 函数测试及真实 API 故障实例通过；只返回通用错误，无资料内容 |
| 格式有效但错误的密钥可能写入混合密文 | 数据库密钥校验标记；所有登录和敏感写入先验证匹配 | 独立错误密钥服务中，读取及注册均返回通用错误，没有创建混合密文用户 |
| 损坏的用户资料不应建立登录状态 | 资料认证解密成功后才创建已登录会话 | 篡改虚构用户资料后登录返回 500，随后 `/auth/me.php` 为 401 |
| 迁移可能破坏 ID、密码及业务关系 | 迁移前加密快照及验证，字段更新事务、维护模式、独立操作员工具 | 独立临时库模拟旧结构、迁移、备份恢复、保留新行及重复迁移通过 |
| Web 运行账号权限过高 | 为本地库配置仅 SELECT/INSERT/UPDATE/DELETE 的新运行账号；凭据私有且不显示 | `runtime_permissions.php` 通过；无建表、触发器、文件或管理授权 |
| 受限账号下，受保护物种删除错误码与 root 不同 | 同时处理数据库外键错误码 1217／1451，保持 409 保护提示 | 先复现 500，再修复；同场景及受限账号回归通过 |
| 密钥／配置可能误提交或被公开访问 | 密钥及加密快照在所有 Git 工作区外；`.env` 被忽略；限制 Windows ACL；生产检查要求密钥和迁移 | 仓库路径拒绝测试、HTTP 私有文件保护及 Git 检查通过；未输出密钥／密码 |
